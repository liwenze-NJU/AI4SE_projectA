# CodeGuard Harness — WebUI 信息架构 (INFORMATION_ARCHITECTURE.md)

> 阶段：SPEC 规约阶段（第一版，待人工评审）。本文档定义页面清单、职责、导航、信息优先级与用户操作流程。
> 视觉与组件契约见 `DESIGN.md`；逐页布局与状态见 `WIREFRAME_SPEC.md` 与 `wireframes/`。

## 1. 全局外壳（App Shell）

所有页面共享同一外壳，保证 Mock 安全表达与导航一致性：

- **顶部 Mock 横幅（常驻、不可关闭）**：琥珀浅底 + 🛡 图标 + "安全 Mock 演示模式"；右侧灰字列明未连接项（真实 Shell / 文件系统 / LLM / API Key / 凭据）。
- **顶栏导航**：左 = `CodeGuard Harness` 字标（非 Vercel logo）+ 当前场景名；中 = 场景选择下拉（三场景）；右 = 当前运行态药丸 + "返回场景"次按钮。
- **底栏声明**：mono 文本 `ScriptedMockLLM · 离线确定性回放 · 不接触真实环境`。
- **外壳响应式**：1366×768 起步；顶栏在窄屏折叠场景选择为抽屉式下拉，Mock 横幅永不折叠。

## 2. 页面清单

| # | 页面名 | 路由概念 | 类型 | 主入口 |
|---|---|---|---|---|
| P1 | 演示场景选择 | `/scenarios` | 全页 | 应用默认首页 |
| P2 | Agent 运行仪表盘 | `/run/:scenarioId` | 全页 | P1 选中场景 → 进入 |
| P3 | 审批交互 | 仪表盘上的模态层 | 模态对话框 | P2 状态机进入 `AWAITING_APPROVAL` 时自动弹出 |
| P4 | 会话结果与 Memory 摘要 | `/run/:scenarioId/result` | 全页 | P2 终态（COMPLETED/FAILED/CANCELLED/LIMIT_REACHED）后进入；或顶栏"查看结果" |

> P3 是仪表盘之上的模态层而非独立路由，但按简报要求作为独立"页面/交互"设计规格。审批结束后模态关闭，回到 P2 继续回放；若审批拒绝则直接进入 P4（FAILED/CANCELLED）。

## 3. 每页职责

### P1 — 演示场景选择
- **职责**：让用户在三个确定性 Mock 场景中选择一个进入回放；建立"这是安全演示"的心智模型。
- **承载信息**：
  - 三张场景卡（每张：编号、场景名、一句话机制、预期护栏结果药丸、Mock 角标）；
  - 顶部一段说明文字：解释 Agent = LLM + Harness、护栏、审批、反馈闭环（教学引言）；
  - Mock 横幅与底栏。
- **不承载**：运行细节、轨迹、真实输入。

### P2 — Agent 运行仪表盘
- **职责**：实时回放一次 Agent 运行的完整状态机迁移、执行轨迹、工具调用与护栏决策；是机制展示的主舞台。
- **承载信息（三栏 + 顶部概览）**：
  - **顶部概览**：水平状态机步进器（9 运行态 + 4 终态分支）、当前态大字 + 药丸、场景名、演示控件（步进/暂停/重放）。
  - **左栏 · 状态机时间线**：垂直 9 态时间线，节点态名(mono)+中文+药丸+时间戳；当前态高亮。
  - **中栏 · 执行轨迹**：按时间序的步骤列表；每步含态名药丸、描述、工具调用展开行（mono 命令 + MOCK 入参 + 结果药丸）；失败行红色边条 + 失败类别 + 诊断折叠。
  - **右栏 · 工具调用与护栏决策**：当前/最近工具调用卡；护栏决策三联（ALLOW/BLOCK/REQUEST_APPROVAL）以三重冗余呈现；风险原因、影响范围。
- **触发 P3**：当回放到 `GOVERNING → REQUEST_APPROVAL → AWAITING_APPROVAL`，自动弹出审批模态并暂停回放。

### P3 — 审批交互（模态）
- **职责**：呈现一个待审批目标动作，给出风险原因与影响范围，由用户批准/拒绝/超时，演示"人工审批"环节。
- **承载信息**：
  - 标题：目标动作（mono，如 `write_file(mock://workspace/src/auth.py)`）；
  - 风险原因列表（带图标 + 文字，如"副作用：修改源文件""可能合法：与测试修复相关"）；
  - 影响范围卡（受影响路径/模块的 Mock 列表）；
  - 超时倒计时（视觉条 + mono 数字，默认如 30s 演示用）；
  - 三按钮：批准（主，黑）、拒绝并停止（危险，红）、稍后（次）；
  - 审批结果反馈：批准→绿 `ALLOW` 药丸回灌轨迹；拒绝→红 `BLOCK`+进入 FAILED/CANCELLED；超时→灰 `TIMEOUT`。
- **关闭后**：回灌到 P2 中栏轨迹并继续回放。

### P4 — 会话结果与 Memory 摘要
- **职责**：终态收束，呈现运行结果、反馈闭环全过程与 Memory 摘要，强化学到的机制。
- **承载信息**：
  - 顶部终态大字 + 药丸（COMPLETED 绿 / FAILED 红 / CANCELLED 灰 / LIMIT_REACHED 黄）+ 场景名 + 耗时/步数 mono 指标；
  - 反馈闭环卡（三段式：第一次失败→反馈分类→Agent 改动作→第二次通过）——场景 3 的核心；
  - Memory 摘要面板：本次会话沉淀的条目（如"已批准决策""项目约定""任务摘要""失败解决方案"），每条带来源时间戳；
  - 护栏决策汇总：本次 ALLOW/BLOCK/REQUEST_APPROVAL 计数；
  - 底部"返回场景选择"主按钮 + "重放本场景"次按钮。

## 4. 页面间导航

```
                 ┌──────────────────────────────┐
                 │  P1 演示场景选择（默认首页）  │
                 └─────────────┬────────────────┘
                               │ 选中场景卡（点击进入）
                               ▼
        ┌──────────────────────────────────────────┐
        │  P2 Agent 运行仪表盘（回放进行中）        │
        │  顶栏：场景下拉 → 可切回 P1；"查看结果"→P4 │
        └──────────────┬───────────────────────────┘
                       │ 回放至 AWAITING_APPROVAL
                       ▼
              ┌────────────────────┐
              │  P3 审批模态（覆盖层）│
              └───┬──────────┬─────┘
           批准/超时│          │拒绝并停止
                  ▼          ▼
        回 P2 继续       直接 P4（FAILED/CANCELLED）
        回放
                       │ 回放至终态
                       ▼
                 ┌────────────────────────────┐
                 │  P4 会话结果与 Memory 摘要 │
                 └──────┬──────────────┬──────┘
            "返回场景选择"│       "重放本场景"│
                        ▼                ▼
                       P1               P2（重置回放）
```

- **顶栏场景下拉**：任何时候可切回 P1 重新选场景。
- **顶栏"返回场景"**：从 P2/P4 回 P1。
- **演示控件**：P2 内"步进/暂停/重放"控制回放进度，不改变页面。
- **键盘**：Esc 关 P3 模态（=稍后/取消）；P4 Enter 聚焦"返回场景选择"。

## 5. 信息优先级（每页）

### P1 场景选择
1. **首要**：三场景卡 + 各自预期护栏结果药丸（机制钩子）。
2. **次要**：顶部教学引言（Agent=LLM+Harness / 护栏 / 审批 / 反馈闭环）。
3. **三级**：Mock 角标、底栏声明。

### P2 仪表盘
1. **首要**：顶部水平状态机步进器 + 当前态大字药丸（一眼看到 Agent 在哪一态）。
2. **次要**：中栏执行轨迹（最近一步在顶部，可向下滚动历史）；左栏状态机时间线。
3. **三级**：右栏工具调用与护栏决策详情、演示控件。
> 当进入 AWAITING_APPROVAL，P3 模态临时成为视觉焦点（遮罩 + 居中），但状态机与轨迹仍可见于背景。

### P3 审批模态
1. **首要**：目标动作标题 + 风险原因列表。
2. **次要**：影响范围卡 + 超时倒计时。
3. **三级**：三按钮 + 审批结果反馈药丸。

### P4 结果与 Memory
1. **首要**：终态大字药丸 + 反馈闭环卡（场景 3 为重点）。
2. **次要**：Memory 摘要面板 + 护栏决策汇总。
3. **三级**：mono 指标（耗时/步数）、返回/重放按钮。

## 6. 用户操作流程（三场景映射）

### 场景 A — 路径逃逸/危险动作被 BLOCK
1. P1 选中"场景 A · 路径逃逸被 BLOCK"卡 → 进入 P2。
2. P2 回放：`INITIALIZING → BUILDING_CONTEXT → DECIDING → GOVERNING`；护栏决策显示 `BLOCK ⊘ 阻止`（红边条 + 风险原因"路径逃逸：目标在 workspace 之外"）。
3. 轨迹显示 Agent 拟调用 `delete(mock://workspace/../system/...)` 被硬阻止；状态机转入 `FAILED`（或 `CANCELLED`，依脚本）。
4. 终态后自动进入 P4：终态红药丸 + Memory 摘要（"危险动作已阻止""路径策略命中"）+ 护栏计数 BLOCK=1。
5. "返回场景选择"回 P1。

### 场景 B — 有副作用但可能合法 → REQUEST_APPROVAL
1. P1 选中"场景 B · 副作用动作待审批" → P2。
2. P2 回放到 `GOVERNING → REQUEST_APPROVAL`，状态机停在 `AWAITING_APPROVAL`，**自动弹出 P3**。
3. P3 展示目标动作 `write_file(mock://workspace/src/auth.py)` + 风险原因（"副作用：修改源文件" vs "可能合法：与测试修复相关"）+ 影响范围 + 倒计时。
4. 用户点"批准"（或等超时）→ P3 关闭，回 P2 轨迹回灌 `ALLOW ✓ 允许`，继续 `EXECUTING → VALIDATING`。
5. 进入 `COMPLETED` → P4：绿药丸 + Memory 摘要（"已批准决策：write_file(auth.py)"）+ 护栏计数 REQUEST_APPROVAL=1/ALLOW=1。
> 变体：用户点"拒绝并停止"→ P4 红药丸（CANCELLED）+ Memory（"用户拒绝 write_file(auth.py)"）。

### 场景 C — 第一次失败 → 反馈分类 → 改动作 → 第二次通过
1. P1 选中"场景 C · 测试失败反馈闭环" → P2。
2. P2 回放：`... → EXECUTING → VALIDATING` → **第一次测试失败**（轨迹红边条 + 失败类别药丸，如"断言失败"+ 诊断详情折叠）→ 状态机 `FEEDING_BACK`。
3. 反馈回灌：Agent 据分类改变下一步动作（轨迹蓝"改动作"行：如改用不同实现/修复）。
4. 重新 `EXECUTING → VALIDATING` → **第二次测试通过**（绿 `ALLOW`/通过药丸）→ `COMPLETED`。
5. P4：绿药丸 + **反馈闭环卡**完整呈现（第一次失败→反馈分类→改动作→第二次通过）+ Memory 摘要（"失败解决方案：断言→validate""第二次通过"）+ 护栏计数。

## 7. 跨页一致性约束

- Mock 横幅、顶栏、底栏在四屏完全一致。
- 状态标签、药丸、图标在四屏同一语义（不出现"COMPLETED 在 P2 绿、在 P4 蓝"的漂移）。
- 字体/间距/色彩令牌统一来自 `DESIGN.md` §3–§5。
- 演示控件仅控制 Mock 脚本回放，所有"执行"文案均标注为"演示步进"，不伪装真实执行。
