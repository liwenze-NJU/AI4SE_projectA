# CodeGuard Harness — WebUI 线框图规格 (WIREFRAME_SPEC.md)

> 阶段：SPEC 规约阶段（第一版，待人工评审）。本文档为各页布局、区域职责、组件状态的**结构化文字规格**；
> 配套低保真 ASCII 线框图见 `wireframes/` 目录（文件清单见 §7）。
> 视觉令牌与组件定义见 `DESIGN.md`；页面职责与导航见 `INFORMATION_ARCHITECTURE.md`。

---

## 0. 约定

- **低保真**：线框仅表达信息架构与区域关系，不含最终视觉、配色像素、真实图片；状态色/药丸以文字标注。
- **状态标注法**：`[默认]` `[悬停]` `[焦点]` `[激活/当前]` `[禁用]` `[空]` `[错误]` `[审批中]` `[完成]`。
- **三重冗余**：凡状态药丸均以 `色 + 图标 + 中文文字` 呈现，本规格中以文字描述三者。
- 全部页面共用外壳（Mock 横幅 + 顶栏 + 底栏），下文每页不再重复，但始终存在。

## 1. P1 — 演示场景选择

### 1.1 布局
单列居中，最大宽 1200px。自上而下：
1. **教学引言区**：H2 标题"理解 Coding Agent Harness 的工作机制" + 一段正文（Agent=LLM+Harness；护栏；审批；反馈闭环）。
2. **场景卡三联**：三张等宽卡片横排（窄屏堆叠），每张含编号徽章、场景名、一句话机制、预期护栏结果药丸、Mock 角标、"进入演示"次按钮。
3. **底部提示**：mono 小字"选择一个场景开始确定性回放"。

### 1.2 各区域作用
| 区域 | 作用 | 信息优先级 |
|---|---|---|
| 教学引言区 | 建立心智模型，降低进入门槛 | 次要 |
| 场景卡三联 | 提供三个确定性入口与预期结果钩子 | 首要 |
| Mock 角标/底栏 | 持续强化"安全演示" | 三级 |

### 1.3 组件状态
- **场景卡**：
  - `[默认]` 白底 + `--elev-ring` 阴影边框；编号徽章 `--meta`。
  - `[悬停]` 升至 `--elev-raised`，左上 4px `--accent` 细条出现。
  - `[焦点]` 卡片整体 `--focus-ring` 2px `--accent`，可键盘选中。
  - `[激活/当前]` 选中后 `--accent` 描边 2px + 卡片轻微上移。
- **预期护栏药丸**：场景 A=`BLOCK ⊘ 阻止`（红浅染）；场景 B=`REQUEST_APPROVAL ? 待审批`（黄浅染）；场景 C=`FEEDING_BACK ↺ 反馈回灌`（黄浅染）→ 终态 `COMPLETED ✓ 已完成`（绿浅染）。
- **"进入演示"按钮**：次按钮（白底阴影边框）。

### 1.4 空状态
- **不适用**：P1 始终展示三张预设场景卡，无空数据态。若未来支持自定义场景且用户未选，则显示"请选择一个确定性 Mock 场景开始"占位（mono，`--meta`）。

### 1.5 错误状态
- 场景脚本加载失败（Mock 资源缺失）：整卡替换为错误卡——`--danger` 左边条 + `✕ 加载失败` 药丸 + mono 诊断 + "重试"次按钮；其余卡片正常可用。

### 1.6 审批状态
- 不适用（P1 无审批环节）。

### 1.7 完成状态
- 不适用（进入 P2 即视为"已选择"，P1 无自身完成态）。

## 2. P2 — Agent 运行仪表盘

### 2.1 布局
顶部全宽概览条 + 下方三栏网格（桌面 3 栏，平板 2 栏，手机单列堆叠）：

- **顶部概览条**（全宽）：左=场景名 + 当前态大字（mono 态名 + 中文）+ 当前态药丸；中=水平状态机步进器（9 运行态 + 4 终态分支）；右=演示控件（`步进 ▶` `⏸ 暂停` `↺ 重放`）。
- **左栏 · 状态机时间线**：垂直 9 态时间线，节点=态名(mono)+中文+药丸+时间戳。
- **中栏 · 执行轨迹**：时间序步骤列表；最近在顶；每步=态药丸+描述+工具调用展开行；失败行红边条+类别+诊断折叠。
- **右栏 · 工具调用与护栏决策**：当前/最近工具调用卡；护栏决策三联卡（ALLOW/BLOCK/REQUEST_APPROVAL）；风险原因、影响范围。

### 2.2 各区域作用
| 区域 | 作用 | 信息优先级 |
|---|---|---|
| 顶部概览条 | 一眼看到当前态与整体进度 | 首要 |
| 左栏 状态机时间线 | 展示显式状态机迁移路径 | 次要 |
| 中栏 执行轨迹 | 回放每一步动作与工具调用 | 次要（当前步骤）/首要（回放焦点） |
| 右栏 工具与护栏 | 展示工具调用详情与治理决策三联 | 三级（细节）/首要（当处于 GOVERNING） |

### 2.3 组件状态
- **水平步进器节点**：
  - `[已完成]` 实心语义色 + 实线连线。
  - `[激活/当前]` 描边语义色 + 节点放大 1.1× + 脉冲点（≤200ms，reduced-motion 关闭）。
  - `[未到达]` 空心 `--meta` + 虚线连线。
  - `[终态分支]` COMPLETED 主路径实线绿；FAILED/CANCELLED/LIMIT_REACHED 侧分支，各自语义色 + 图标 + 文字。
- **状态机时间线节点**：同步步进器；当前态药丸 + mono 时间戳。
- **轨迹步骤行**：
  - `[默认]` `--border-soft` 行分隔。
  - `[悬停]` 行底 `--surface-warm`（等同 `--surface`，Vercel 无暖层）轻微变化。
  - `[展开]` 工具调用展开行显示 mono 命令 + MOCK 入参 + 结果药丸。
  - `[失败行]` 左 4px `--danger` 边条 + 失败类别药丸 + 诊断折叠区（默认折叠）。
- **演示控件**：`[默认]` 次按钮；`[激活]` 当前态按钮 `--fg` 黑底白字；`[禁用]` 当回放至终态时 `步进` 禁用。
- **护栏决策三联卡**：每卡=药丸 + 图标 + 文字 + 一行原因；当前命中态高亮（边框语义色 2px），其余淡化。

### 2.4 空状态
- **回放未开始**（进入 P2 尚未点"步进"）：三栏显示占位——状态机时间线首节点 `INITIALIZING` 灰圈脉冲、轨迹区"等待开始演示回放"（mono，`--meta`）、右栏"尚无工具调用"。

### 2.5 错误状态
- **轨迹失败行**：见 §2.3 失败行；为"可恢复错误"（场景 C），后续出现 `FEEDING_BACK` 蓝行与"改动作"步骤。
- **Mock 回放中断**（脚本异常）：顶部概览条右侧显示 `✕ 回放中断` 红药丸 + mono 诊断 + `↺ 重放`；三栏保留已回放内容。

### 2.6 审批状态
- 当状态机进入 `AWAITING_APPROVAL`：回放自动暂停；中栏轨迹最后一步标注 `⏸ 等待审批` 黄药丸；**P3 模态弹出**（见 §3）；右栏护栏决策卡高亮 `REQUEST_APPROVAL ? 待审批`。
- 审批结束（批准/超时）：模态关闭，轨迹回灌 `ALLOW ✓ 允许`（绿）或 `TIMEOUT ◷ 超时`（灰），步进器继续。
- 审批结束（拒绝）：模态关闭，轨迹回灌 `BLOCK ⊘ 阻止`（红），状态机转入 `CANCELLED`/`FAILED`，进入 P4。

### 2.7 完成状态
- 进入任一终态：顶部概览条当前态大字换为终态药丸（COMPLETED 绿/FAILED 红/CANCELLED 灰/LIMIT_REACHED 黄）；步进器终态分支点亮；`步进` 禁用、`查看结果` 主按钮出现（→P4）。

## 3. P3 — 审批交互（模态层）

### 3.1 布局
遮罩 `hsla(0,0%,98%,1)` 半透明 + 居中卡片（最大宽 560px，`--elev-raised`，8px）。自上而下：
1. **标题行**：mono 目标动作（如 `write_file(mock://workspace/src/auth.py)`）+ `REQUEST_APPROVAL ? 待审批` 药丸。
2. **风险原因列表**：带图标的条目（如"副作用：修改源文件"⚠、"可能合法：与测试修复相关"ℹ）。
3. **影响范围卡**：受影响路径/模块的 Mock 列表（mono，`MOCK` 角标）。
4. **超时倒计时**：视觉条（`--warn` 填充递减）+ mono 数字"剩余 00:23"。
5. **三按钮行**：`批准`（主，黑）/ `拒绝并停止`（危险，红）/ `稍后`（次）。
6. **结果反馈区**（审批动作后短暂出现）：批准→绿 `ALLOW ✓ 已批准`；拒绝→红 `BLOCK ⊘ 已拒绝`；超时→灰 `TIMEOUT ◷ 已超时`。

### 3.2 各区域作用
| 区域 | 作用 | 信息优先级 |
|---|---|---|
| 标题（目标动作） | 明确被审批的是什么 | 首要 |
| 风险原因列表 | 解释为何需人工 | 首要 |
| 影响范围卡 | 量化副作用边界 | 次要 |
| 倒计时 | 演示超时机制 | 次要 |
| 三按钮 | 人工决策入口 | 首要 |
| 结果反馈区 | 闭环回灌前的视觉确认 | 三级 |

### 3.3 组件状态
- **模态整体**：`[进入]` ≤200ms 透明度（reduced-motion 即显）；焦点陷阱，首个焦点=`批准`按钮；Esc=`稍后`。
- **倒计时**：`[运行]` `--warn` 条递减 + mono 数字；`[将超时]` 最后 5s 文字与条转 `--danger` + 图标；reduced-motion 下数字仍可见（不依赖动画）。
- **按钮**：
  - `批准` `[默认]` 黑底白字；`[悬停]` `color-mix` 提亮；`[焦点]` `--focus-ring`；`[禁用]` 审批已提交后禁用。
  - `拒绝并停止` `[默认]` 红底白字或 ghost+红字；`[焦点]` 焦点环。
  - `稍后` `[默认]` 次按钮。
- **风险原因条目**：`[默认]` `--border-soft` 分隔；`[悬停]` 行底浅染。

### 3.4 空状态
- 不适用（模态仅在有待审批动作时弹出，必含目标动作与至少一条风险原因）。

### 3.5 错误状态
- **倒计时归零未操作**：自动判定 `TIMEOUT`，等同"稍后/默认拒绝"语义（依脚本：场景 B 超时→回灌灰 `TIMEOUT`，状态机继续或转 CANCELLED）。
- **审批提交失败**（Mock 异常）：结果反馈区显示 `✕ 提交失败` 红药丸 + mono 诊断 + `重试`，模态保持打开。

### 3.6 审批状态（本模态即审批状态机）
- `待审批`（默认）→ 用户操作或超时 → `已批准`/`已拒绝`/`已超时` → 回灌 P2 轨迹 → 模态关闭。

### 3.7 完成状态
- 审批动作提交后，结果反馈药丸显示约 1.5s（reduced-motion 下为静态文字），随后模态关闭、焦点回到 P2 轨迹最后一行。

## 4. P4 — 会话结果与 Memory 摘要

### 4.1 布局
单列居中，最大宽 1200px。自上而下：
1. **终态头条**：终态大字（mono 态名 + 中文）+ 终态药丸 + 场景名；右侧 mono 指标（耗时 / 步数 / 护栏计数）。
2. **反馈闭环卡**（场景 C 重点，A/B 简化）：三段式横向流程——① 第一次失败（红）→ ② 反馈分类（黄，类别药丸）→ ③ Agent 改动作（蓝）→ 第二次通过（绿）；编号箭头连接。
3. **Memory 摘要面板**：条目列表，每条=类型药丸 + 摘要文字 + 来源时间戳(mono)。
4. **护栏决策汇总**：三计数卡（ALLOW/BLOCK/REQUEST_APPROVAL 各一，数字 mono 大字 + 药丸）。
5. **底部操作**：`返回场景选择`（主，黑）+ `重放本场景`（次）。

### 4.2 各区域作用
| 区域 | 作用 | 信息优先级 |
|---|---|---|
| 终态头条 | 一眼判定本次结局 | 首要 |
| 反馈闭环卡 | 复现"失败→反馈→改动作→通过"闭环 | 首要（场景 C） |
| Memory 摘要 | 展示会话沉淀 | 次要 |
| 护栏决策汇总 | 量化治理行为 | 次要 |
| 底部操作 | 导航收束 | 三级 |

### 4.3 组件状态
- **终态药丸**：COMPLETED 绿/FAILED 红/CANCELLED 灰/LIMIT_REACHED 黄，图标+文字。
- **反馈闭环卡段**：每段=语义色边条 + 编号圆 + 药丸 + 简述；箭头 `→` `--meta`。
- **Memory 条目**：`[默认]` `--border-soft` 分隔；类型药丸（如"已批准决策""项目约定""任务摘要""失败解决方案"）；`[悬停]` 行底浅染。
- **计数卡**：mono 大数字 + 药丸；零计数淡化（`--meta`）。

### 4.4 空状态
- **无 Memory 条目**（理论不发生，因场景均有沉淀）：显示"本次会话无 Memory 沉淀"（mono，`--meta`）。
- **非闭环场景的反馈卡**（A/B）：显示简化版"本次未触发测试反馈闭环"（mono，`--meta`），或仅展示对应终态路径。

### 4.5 错误状态
- 不适用（P4 为终态收束页，错误已在 P2 呈现；若 Memory 解析失败，Memory 面板显示 `✕ 摘要不可用` 红药丸 + mono 诊断，其余正常）。

### 4.6 审批状态
- 不适用（P4 不进行审批；但 Memory 摘要会回显本次审批结果条目，如"已批准决策：write_file(auth.py)"）。

### 4.7 完成状态
- P4 即"完成态"页面本身；`返回场景选择`回 P1、`重放本场景`回 P2 重置回放。

## 5. 跨页公共状态规格

### 5.1 Mock 横幅（常驻）
- `[常态]` 琥珀浅底 + 🛡 图标 + "安全 Mock 演示模式" + 未连接项清单。
- 无关闭、无折叠、四屏一致。

### 5.2 顶栏
- 场景下拉 `[默认/悬停/焦点]`；当前态药丸实时反映 P2/P4 状态；`返回场景` 次按钮。

### 5.3 键盘与焦点
- 全页 Tab 顺序：Mock 横幅（仅文本）→ 顶栏场景下拉 → 主内容首要交互 → 底栏。
- P3 模态打开时焦点陷阱；关闭后焦点回触发元素。
- 所有交互 `--focus-ring` 2px `--accent` 可见。

### 5.4 reduced-motion
- 全局：移除脉冲、倒计时条动画改为静态数字 + 文字"剩余 00:23"、模态即显即隐；状态仍由色+图标+文字表达。

### 5.5 窄屏自适应（<768px）
- 桌面优先，目标宽度 1366×768 及以上。窄屏只保证基本可读、可滚动和可操作，不承诺与桌面端相同的信息密度和视觉效果。
- 多栏仪表盘（P2）按顺序堆叠为单栏：顶部概览条 → 状态机时间线 → 执行轨迹 → 工具调用与护栏决策。
- Agent 状态步进器保持横向滚动，不额外重构为另一套状态组件。
- 表格和较宽 Trace 内容允许在组件内部横向滚动。
- 审批模态（P3）宽度限制在视口内，按钮可纵向排列。
- 不得出现页面级不可控横向溢出。
- Mock Demo Mode 横幅保持可见。
- 关键按钮触达区域保持至少 44×44px。
- 不创建独立移动端页面、移动导航或专门的移动端交互流程。
- 自动化验收至少检查 375px 宽视口：页面可打开、关键文字可读、场景可选择、审批可批准或拒绝、显式滚动区域可用、不存在遮挡关键按钮的布局错误。

## 6. 状态汇总速查

| 场景 | 关键状态序列 | 终态 | 核心展示组件 |
|---|---|---|---|
| A 路径逃逸 | DECIDING→GOVERNING→(BLOCK)→FAILED/CANCELLED | FAILED/CANCELLED | 护栏 BLOCK 三联卡 + 红边条轨迹 |
| B 副作用待审批 | GOVERNING→REQUEST_APPROVAL→AWAITING_APPROVAL→[P3 批准]→EXECUTING→VALIDATING→COMPLETED | COMPLETED | P3 模态 + ALLOW 回灌轨迹 |
| C 失败反馈闭环 | EXECUTING→VALIDATING(失败)→FEEDING_BACK→(改动作)→EXECUTING→VALIDATING(通过)→COMPLETED | COMPLETED | 反馈闭环卡 + 失败类别药丸 + 诊断折叠 |
